capscope never trains anything. It runs the frozen checkpoint forward over the batches you supplied, records what every module outputs, and takes the singular value decomposition (SVD) of two kinds of matrix: each module's activations and each module's weights. Almost every number in the panel is read off one of those two spectra, or off the loss after a weight has been deliberately damaged. This guide says, for each section, what is computed, how, and how to read it.

Almost every wrong conclusion comes from reading one metric in isolation: a module can show a full spectrum because it is capacity-bound, because its input is narrow, because a nonlinearity inflated the rank, or because it was never trained. The verdict engine sorts between those four; the sections below explain what it sorts with.

SVD in one paragraph

Any matrix X can be written as X = U Σ Vᵀ: a set of orthogonal input directions (rows of Vᵀ), a matching set of orthogonal output directions (columns of U), and one number per pair, the singular value σᵢ, saying how much X stretches along that pair. The σᵢ are sorted largest first. The rank of X is how many of them are non-zero. Keeping only the k largest and zeroing the rest gives the rank-k approximation Xk = U[:, :k] · diag(σ₁…σk) · Vᵀ[:k, :], the closest rank-k matrix to X (Eckart–Young). Two uses follow:

  • On an activation matrix (rows = samples, columns = units, columns mean-centred), σᵢ² is the variance of the data along the i-th principal direction. This is PCA: the singular values say how many directions the outputs actually spread across.
  • On a weight matrix W of shape [out, in], σᵢ says how strongly W amplifies its i-th input direction. Replacing W by Wk keeps the layer's shape but lets it pass information along only k directions; everything it did along the other min(in, out) − k directions is deleted.

Rank and saturation (activations)

What is done. During the forward passes a hook on every module takes its output tensor, flattens it to [N, D] (D = the module's output width, N = every row: tokens, nodes, pixels, samples), and keeps a random subset of rows so that about 4096 are collected across the captured batches. The columns are mean-centred. The SVD of that [N, D] matrix gives D singular values σ₁ ≥ … ≥ σD; the left chart plots them on a log scale, the right chart plots the cumulative share of Σσᵢ².

The summary numbers, all functions of the same spectrum:

MetricHow it is computedRangeWhere it misleads
Effective rankNormalise the singular values to sum to 1, pᵢ = σᵢ / Σσ; take the Shannon entropy H = −Σ pᵢ log pᵢ; report exp(H). Equals k when k directions share the spread equally.1 to DInflated by any nonlinearity: a ReLU on a rank-8 input can read far above 8. Never a verdict input on its own.
Stable rankΣσᵢ² / σ₁²1 to DIgnores the tail almost entirely, so it reads low whenever one direction dominates even when many others carry real signal.
Participation ratio(Σλᵢ)² / Σλᵢ² with λᵢ = σᵢ²1 to DAgrees with effective rank on clean spectra, diverges on heavy tails.
Numerical rankCount of σᵢ above σ₁ · max(N, D) · ε (float32 machine epsilon)0 to DA precision count. It saturates at D long before the module uses D dimensions well.
Rank at 90 % / 99 % energySmallest k such that Σi≤k σᵢ² is 90 % (99 %) of Σσᵢ²1 to DThe most robust activation-only measures, but blind to whether the loss needs those directions.

How to read it. When they disagree, trust rank at 99 % energy over effective rank, and trust the truncation sweep over both. A large gap between numerical rank and rank at 90 % energy means a long low-energy tail: many directions carrying a little signal each. Without a sweep that is the best available hint that a module is filling up; with a sweep, the sweep wins outright, because a full-looking activation tail after a nonlinearity is common and says nothing about whether the loss needs those directions. In the spectrum chart, a sharp cliff means the module lives in far fewer dimensions than it has; a smooth decay reaching the noise floor only near D means there is no spare subspace to reclaim.

Truncation sweep (loss)

What is done. This is the only measurement that asks the loss rather than the activations, and it runs only when you pass loss_fn. For one module at a time:

  1. Every ≥ 2-D parameter inside the module (its weight, or all its descendants' weights jointly for a container) is decomposed once: W = U Σ Vᵀ, keeping the original copy.
  2. For a rank k from a log-spaced grid (1, 2, 3, 5, 8, … up to the full rank), each of those weights is overwritten with its rank-k approximation Wk, the model is run forward over the first few batches, and the loss is recorded.
  3. The smallest k on the grid whose loss stays within rel_tol (1 %) of the untouched model's loss is refined by bisection down to the exact smallest k. The weights are then restored.

The numbers. used rank is that smallest k: the number of directions of its weight the loss actually needs. Because the curve is not monotone, the panel also gives a conservative used rank: one above the largest evaluated rank that was still over tolerance, so a lucky dip below the threshold at a low k does not count. When the two differ, the curve wobbles around the threshold and the conservative one is the number to size a layer by. max rank is the largest min(in, out) among the swept weights. used % is used rank over the module's output width; the verdict thresholds apply to this. marginal pressure is the relative loss increase at rank used − 1, which the bisection always evaluates. By construction it is at least the tolerance (used − 1 is outside the band, that is what made used the answer), so "+1 %" means "just outside the band": the loss is indifferent to the last directions. Read below about 5 % as indifferent, 5–20 % as mild, above 20 % as genuinely pressed; a module whose last direction costs 30 % of the loss needs that direction, one that costs 1 % does not, even at the same used %. loss at half the used rank and the table of every (k, loss) the sweep evaluated show the shape of the curve left of the marker: a steep climb means the directions below used are each doing work, a flat stretch means the module could lose many of them. loss at rank 1 is what destroying the module costs. Without a sweep (a module with no matrix weights, or a run without loss_fn) used rank falls back to the rank at 99 % activation energy and the field's description says so; that fallback is an activation-only number and inherits their inflation by nonlinearities.

Noise and wobble. Every point of the (k, loss) table is computed on the same sweep batches with the same weights, so the table has no sampling noise: a step like "+1.4 % at k = 39, +0.8 % at k = 43" is real. Truncation is simply not monotone in k, because dropping the 40th direction can remove something the 41st was compensating for, and a truncated model scoring slightly below the base loss is the same effect (the removed direction was slightly hurting on these batches). What is uncertain is how much the answer depends on which batches were used; the panel reports that as the batch-to-batch spread of the base loss. When that spread is far larger than the 1 % tolerance, used rank is a property of these batches as much as of the model, and would move by a few directions on other data. Read the table's overall slope for the shape of the curve, and treat used rank as ± a few directions, not an exact count.

Activation rank versus sweep rank. The two can disagree, and the disagreement is informative rather than an error. A 15-input layer whose output variance is 99 % explained by 9 directions can still need all 15 weight directions: variance measures how much the outputs move, the sweep measures whether the loss cares. Small-variance directions are often exactly the ones the heads read (a rare label, a fine distinction), so the loss can depend strongly on directions that barely register in the activation spectrum. That is why the sweep, not the activation rank, decides.

Leaf versus container sweeps are separate experiments. A container's sweep truncates all its weights to the same k at once, so its used rank is not the max of its children's: joint truncation can land within tolerance at a k where truncating one child alone did not, because the loss curve is not monotone and the bisection returns the crossing it finds, not a global one. Read a container's number as "what this block needs when all of it is squeezed together" and a leaf's as "what this one weight needs with everything else intact". For choosing the width of a layer, use the container's number, and its conservative variant when the two differ: that is the experiment where the whole layer is narrowed. The leaf numbers say which path inside the layer carries the load, and a leaf that ranks above its own container in the list is telling you about that path, not about the layer's width. A leaf can "need" more directions than its container because truncating one weight alone breaks a balance with its sibling that truncating both together preserves; and a weight can need more directions than its input has rank, because the weight's own singular directions are not aligned with the input subspace, so several of them are needed to span it. Neither means "more information is flowing than the input holds". The base loss is loss_fn evaluated on the first sweep batches of the loader you passed (the header says how many), so it is comparable to a training or validation loss only if that loader is training or validation data. The sweep uses whatever scalar loss_fn returns; for a multi-head model that is usually a sum over heads, and the tool does not decompose it per head.

What the tool does not know: which child reads which input. In a SAGE-style layer with lin_l and lin_r, the panels show both fed by the previous layer, because both read the same tensor before the layer aggregates it; whether a given child sees the node's own features or the neighbour mean is in the model's forward, not in the report. If two siblings show very different pressure, that is a real finding about which input path the loss relies on, but naming the paths needs the code.

Weight rank cap is what stops this being misread. A Linear(15 → 128) has weight rank at most 15 because of its input, so "the loss needs all 15 directions" is about the 15-dimensional input, not about whether 128 outputs are enough. The tool tags each module by the weight producing its output: input-capped (in < out), output-capped (out < in) or square. Output-capped or square with a high used % is evidence to widen this module; input-capped with a high used % is evidence to widen whatever feeds it, and the verdict engine routes that to upstream. For a container the cap comes from the leaf that produces its output, not the narrowest weight anywhere inside it: a four-layer stack whose first layer takes 15 inputs is not capped at 15 as a whole, because the nonlinearities between its layers let later layers use their full width, and the sweep measures that.

Cautions. The sweep costs one forward pass over the sweep batches per rank step per module, so on a large model start without loss_fn, read the activation ranks, then sweep. On an undertrained checkpoint it reports used rank 1 almost everywhere, because destroying weights costs nothing when nothing has been learned; the header warns when half or more of the swept leaves show that.

Weight spectrum (alpha)

What is done. This uses the weights only, so it is the one thing the data-free mode reports. For each matrix weight (convolutions flattened to [out, in·k·k]) take the singular values of W and square them to get the eigenvalues λ₁ ≥ λ₂ ≥ … of WᵀW. Fit a power law to the tail with the Hill estimator over the top tenth (k = n/10, at least 1):

alpha = 1 + k / Σi≤k log(λi / λk+1)

A module's alpha is the median over its matrix weights; the gauge shows each weight as a dot and the module value as the marker. The small charts under it are the weights' own singular values, with the sweep's used rank marked.

How to read it. Following Heavy-Tailed Self-Regularisation (Martin and Mahoney), alpha tracks how far a layer's spectrum has moved from its random initialisation:

AlphaWhat it meansWhat to do
above 6Spectrum still close to the random baseline; little task structure has formedMore steps, more data or a different learning rate. Not more width.
2 to 6Correlations have built up; the layer is well conditionedJudge capacity on the rank metrics and the sweep.
below 2Over-trained, tending toward memorisationRegularisation or more data, not more width.

Alpha earns its place because a layer that has learned nothing and a layer that has learned everything it can both show a saturated-looking activation spectrum; alpha tells you which you are looking at. On a small matrix it is not a fit at all: with 15 eigenvalues the "top tenth" is k = 1 and the formula reduces to one ratio of the two largest eigenvalues. So on matrices with fewer than 20 eigenvalues (the threshold alpha_min_rank) the panel prints "not reliable" instead of a reading and the undertrained verdict is not applied; between 20 and about 50 treat the reading as indicative. If the median alpha over all leaves is above 6, the header warns that the whole checkpoint looks undertrained.

Graph: oversmoothing

What is done. Only when you pass edge_index_fn, and only for modules whose output has one row per node of the batch. For such an output X (centred by subtracting the mean row), the tool computes the Dirichlet energy: the mean over edges (i, j) of ‖xᵢ − xⱼ‖², divided by the mean over nodes of ‖xᵢ − x̄‖². Random independent features give about 2, features that have collapsed onto their neighbours give 0. MAD is the mean cosine distance between each node and its neighbours, on the raw features. Both are averaged over the captured batches.

How to read it: the decay, never the level. A common offset makes any normalised energy look small without smoothing having occurred (post-ReLU activations all sit in the positive orthant). Centring removes the offset, and the verdict still only uses the ratio to the nearest upstream module that has a Dirichlet reading, shown as vs nearest upstream graph layer. Oversmoothed fires only when energy is below 0.05 in absolute terms and below 30 % of that upstream value. It answers a different question from the rest of the panel: not "is this module out of room" but "has message passing destroyed the distinctions between nodes", and widening cannot fix that.

MAD is shown but not trusted. When every feature dimension shares a sign, cosine distances collapse toward zero regardless of how distinct the nodes are, which after a ReLU is the normal state. Use it as corroboration only.

The upstream reference is the nearest module feeding this one that has a Dirichlet reading, never the module's own child: a layer that computes its own output is compared with the previous layer's output, and a path inside a layer (a child) is compared with the layer that feeds it. To read decay hop by hop, compare the layers' outputs (the containers) in execution order. Two sibling paths with very different energy are a real observation about what each reads (a neighbour mean is smoother than the node's own features), and a reasonable basis for telling them apart, but the tool itself does not know which is which.

The first graph layer has no upstream reading, so its level alone is not used by the verdict and should not be read as smoothing: a neighbour-mean path is smooth by construction, and a low first value is expected. What matters is whether energy keeps falling layer after layer.

Redundancy and unit health

What is done. Three checks on the same sampled activation matrix, plus one across modules:

  • Dead units: columns whose variance over the samples is below 10⁻⁶ of the mean column variance.
  • Duplicate units: standardise the live columns, take the correlation matrix, and flag every column whose absolute correlation with an earlier column exceeds 0.95.
  • Activation histogram: the distribution of the sampled output values, with the fraction that are exactly zero.
  • Linear CKA between this module's activations X and every other captured module's Y, over the same sampled rows: CKA = ‖XᵀY‖²F / (‖XᵀX‖F ‖YᵀY‖F). It is 1 when the two hold the same representation up to a linear map.

A module without matrix weights (an activation, a norm, a pooling op) has nothing to truncate, so its "used rank" in the list and the capacity section is the activation rank at 99 % energy, drawn dimmed and marked "≈" in the list. That number is inflated by the nonlinearity itself: a GELU output reading 91 directions after a Linear that needed 65 is the nonlinearity spreading the same information over more directions, not new capacity.

Activation scale (the std and range in the histogram) enters none of the metrics: singular-value ratios, CKA, correlations and the Dirichlet ratio are all normalised. The histogram is a sanity check, not an input to any verdict.

How to read it. These find width that is already present and going unused, the counter-evidence to every saturation reading: a module cannot be short of capacity while wasting a third of what it has. Dead plus duplicate above 35 % gives a redundant verdict that pre-empts saturation; below about 10 % neither says much. The duplicate signal is the stronger one, since a dead unit may be an unlucky initialisation but a duplicate is width the optimiser chose to spend on a copy. A spike at zero in the histogram means a mostly-dead ReLU; values pinned at the extremes of a bounded activation mean saturation in the classical sense.

CKA between consecutive layers is usually high (0.8–0.95) and that is not redundancy: it says each layer mostly preserves the representation it receives and changes it along a few directions. The sweep can say at the same time that the layer's weights matter a great deal (losing them multiplies the loss), because the loss lives in exactly those few changed directions. Only above 0.98, with an unrelated module, does similarity become evidence that two modules do one job; a 0.9 chain is a normal trunk.

Best unrelated CKA excludes relatives (a Sequential returns exactly its last child's output, so parent and child trivially score 1.0) and anything downstream of the module (a consumer that merely copies its input is the consumer's problem). Above 0.98 two modules are doing one job and widening either is unlikely to pay. The heatmap and the neighbour list still show every pair; look for dark square blocks along the diagonal, a run of consecutive modules collapsed onto one stage of computation.

Dataflow graph and upstream carry

What is done. On the first batch the model is run with gradients enabled and each module's output tensor is registered by its autograd node. Each module's inputs are then walked backwards through the autograd graph until a registered producer is met: that is an edge. Functional ops (F.relu, index_add_, scatter, concatenation) are simply steps on the walk, which is why hand-written message passing does not break it. Graph nodes are the leaves plus every container that builds its own output rather than handing a child's through, such as a SAGEConv returning lin_l(agg) + lin_r(x); those are labelled "container that computes its own output" and drawn as a box inside their own hull. Container-level edges are projections of node edges, and the root is never a node.

Upstream carry is then propagated forward along that graph: carry(M) = min(in_dim(M), Σproducers P min(width(P), carry(P))). A source module carries its own input width. It is the narrowest point along the paths feeding a module, and it encodes a constraint none of the per-module metrics can see: a module downstream of an 8-dimensional path cannot hold more than 8 dimensions of information however wide it is, even though a ReLU on that path can show an effective rank of 40.

Limits. Producers are summed, which is right for a concatenation or a sum of maps of different tensors (a SAGE layer reading x and the neighbour mean of x genuinely has up to twice the rank) and an over-estimate when several producers carry the same information. The tool cannot tell those apart: a layer whose two children both read the same tensor doubles its carry at every hop (15 → 30 → 60 → 120 in a four-layer SAGE stack). Functional ops on the same tensor (a rig-wide mean, a concatenation of a tensor with a pooled copy of itself) add no producer and so no carry, because they create no new information source. Past the first layer of a message-passing stack, carry is a rough floor, not a number to act on. And it treats message passing as pointwise: aggregation brings in other nodes' features, which carry does not count. So carry is a floor on what could be missing upstream, not an exact figure.

Verdicts and priority

What is done. With every number above in hand, the rules below are evaluated in order per module and the first match wins. The thresholds live in capscope.THRESH, can be overridden per run with inspect(thresholds=...), and the values used are recorded in the report. Every verdict above saturated describes a condition under which a module looks capacity-bound but is not, which is why they pre-empt it; if you change the thresholds, keep the order.

VerdictFires whenWhat it means for you
narrowWidth below 8An output head or a very narrow layer. Width is set by the task; capacity metrics do not apply.
passthroughLeaf with no parameters of its ownAn activation, dropout or pooling op. Nothing to widen; the sentence names the module feeding it.
oversmoothedDirichlet below 0.05 and below 30 % of the nearest upstream graph layerWidening will not help. Residual connections, normalisation, or fewer hops.
upstreamCarry is below the width and used rank is within 10 % (± 1) of the carry; for a leaf the used rank is first capped by its weight rankIt uses everything that arrives, so it is relaying, not saturating. The sentence says where to widen instead.
undertrainedAlpha above 6Needs steps, data or a different learning rate before it needs neurons.
redundantOver 35 % dead or duplicate units, or CKA above 0.98 with a module that is neither a relative nor downstreamThe width already here is not being used. Prune or regularise before widening.
saturatedUsed rank above 85 % of widthA genuine growth candidate. Check the rank cap: input-capped means widen upstream first.
tightUsed rank above 60 %Second-tier candidate; some headroom remains.

The reading line under the header says, before any per-module number, whether the list is worth acting on: which modules are the top width candidates, whether any of them is under real pressure, and whether the first layer is simply consuming everything the raw input offers. A top-four that is all tight with +1–2 % pressure is an ordering among modules the loss is indifferent to; the right conclusion is "nothing here is width-limited", and the next questions are input features, data, optimisation and head conflict, not which of the four to widen.

Priority is the 0 to 1 score the module list sorts on. It is a ranking device, not a measurement: read the ordering, not the number. Saturated scores 0.70 plus up to 0.15 for used % and 0.15 for marginal pressure; tight 0.35 plus up to 0.20 for how far past 60 % it is and 0.10 for pressure; spare up to 0.15; upstream 0.12, undertrained 0.08, redundant and oversmoothed 0.05; passthrough and narrow 0. Input-capped saturated or tight modules are multiplied by 0.6 (widen upstream instead), and any output layer (a sink of the graph) by 0.5, because its width is fixed by the task.

Reading them together

No single metric decides anything. A full-looking activation spectrum is the entry point, not the conclusion, and four checks stand between it and a decision to spend parameters: is the checkpoint trained (alpha, the header warning), is the module relaying a narrower input (carry, rank cap), is its width already wasted (dead and duplicate units, CKA), and is the loss actually pressing on its last directions (the sweep, marginal pressure). Only the path through all four ends in more width.

  1. Check the training loss first, outside this tool. If training loss is also stuck, the problem is capacity or optimisation. If training loss is low while validation is flat, no amount of width will help.
  2. Read the header. An undertrained warning invalidates every other reading. A "no dataflow edges" warning means the graph and the carry are missing, so the upstream verdict could not fire.
  3. Scan the alpha column for anything above 6.
  4. Take the top three or four by priority and confirm each with its sweep chart: the used-rank marker should sit near the right with the loss climbing steeply to its left. A flat curve means the loss does not care, whatever the activation rank says.
  5. Check the rank cap and the carry of each candidate. Input-capped means the widening belongs one layer earlier.

What none of these can tell you

Every metric here is descriptive. They characterise the state a trained model has arrived at; none predicts what a larger model would do.

  • How much to add. A saturated module tells you the direction, not the size. Size estimates need gradient-based growth criteria, which need a backward pass and are not in the tool.
  • Whether the extra width will be used. Saturation says the current width is fully occupied, not that the task has more structure waiting to be captured.
  • Task interference between heads. Nothing here sees it. For a multi-head model, take the pairwise cosine similarity of each head's gradients with respect to the shared trunk; persistently negative similarity means the plateau is conflict rather than capacity.
  • Depth versus width. Every metric here is about a module's dimensionality, not about layers, hops or aggregation.
  • Data limits. If the plateau comes from label noise or from the task being saturated at your dataset size, the whole model will look healthy and no verdict will fire.
